# 原图本站下载缓存

此功能把 NewAPI 图片结果中的上游 URL 换成 `https://本站/v1/image-results/<加密凭证>`。普通 Images、Edits JSON、Images SSE 完成事件及 Responses `image_generation_call` 图片结果共用缓存；原有 Base64、usage、图片数量和生成重试规则不变。已适配的 Ali、Jimeng、MiniMax、Replicate Images URL 输出同样替换。视频、聊天文本里的链接、参考图和未完成的中间图不改写。

## 行为

- 收到结果后启动有限并发的原图 GET，下载并核验字节完整性、类型后，AES-256-GCM 加密原子写入磁盘。生成响应不等待下载，不会因为下载故障触发渠道重试。
- 每张原图并发合并、每轮最多 2 次 GET；失败冷却 30 秒。浏览器断开不会取消服务器正在进行的下载；服务器停止时取消下载，不发送生成请求。
- 下载链接有效期 24 小时，持有链接即可下载，不要求第三方浏览器附带 API Key。凭证加密且防篡改，不包含客户 Key。**链接属于访问凭证，不应公开传播。**
- 缓存及下载凭证依赖固定密钥，保留目录和密钥即可跨容器重启恢复；到期清理缓存，不是永久图库。原图最大 32 MiB，缓存上限 10 GiB，下载并发 4，等待/冷却任务最多 128，解密交付并发 4。
- 接口支持 GET、HEAD、Range；附加 `?download=1` 使用下载文件名。下载失败返回 503 与 Retry-After，只可重试同一下载地址；到期返回 410。此接口不进入渠道分配、额度扣减或生成处理器。
- 下载不转发 Key/Cookie；沿用现有 fetch 域名/IP 规则，额外强制禁止内网，校验重定向和拨号 IP，拒绝 SVG/HTML，使用正常 TLS 验证。不能靠关闭全局 SSRF 开关放行缓存内网访问。

## 启用条件（尚需按生产变更流程部署）

未设置 `IMAGE_RESULT_CACHE_PUBLIC_BASE_URL` 时功能关闭，便于兼容旧部署。启用需要三个环境变量：

| 变量 | 要求 |
| --- | --- |
| `IMAGE_RESULT_CACHE_PUBLIC_BASE_URL` | 客户能访问的 NewAPI HTTPS 根地址，不从请求 Host 或 Forwarded 头推导 |
| `IMAGE_RESULT_CACHE_DIR` | 专用持久化目录，例如挂载卷内的 `/data/image-results` |
| `IMAGE_RESULT_CACHE_KEY_FILE` | secret 挂载文件，内容为独立随机 32 字节密钥的 hex 或 Base64；不要使用客户 Key |

下载域名必须将 `/v1/image-results/` GET/HEAD 转发至此 NewAPI 实例，不能重定向登录页。多实例需对同一 URL 固定实例或使用具有一致读写语义的共享缓存方案；当前磁盘总量限制和单次下载合并为进程内实现，**不支持多个进程同时写入同一缓存目录**。多实例可用相同密钥、独立目录，但每个实例会各自下载和缓存。

NewAPI 的访问日志会遮蔽凭证路径；**部署时也要对 Caddy/CDN/负载均衡的该路径关闭 URL 记录或进行脱敏**。不应在第三方分析平台、工单或公开页面记录完整下载链接。

## 验证与回滚

本地测试使用模拟图片响应，不调用真实生图接口。检查同一图片第一次取回后多次 GET、重启、上游不可用时缓存仍可读，以及图片计数/usage 未变化。

回滚应用镜像或关闭配置会恢复旧响应方式，但先前已发出的本站链接仍需要下载路由和相同密钥；正式回滚应保留新下载服务至少到已发链接到期，不能直接撤销路由或删除缓存。旧的上游 URL 不会被自动改写；也不会扫描客户历史或重新生成旧任务。
