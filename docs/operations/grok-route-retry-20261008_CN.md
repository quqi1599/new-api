# 已知不可用入口的请求级排除

## 技术契约

有实际收到的上游响应，且精确机器码与状态匹配时，下列入口在当前请求的后续轮次中保持排除：

| 机器码 | 状态 |
|---|---|
| `model_not_supported`、`model_not_found` | 404 |
| `model_cooldown` | 429 或 503 |
| `upstream_connection_refused` | 502 |

兼容旧 CPA HTTP 503 的 `auth_not_found` 机器码，以及 trim/lower 后严格位于说明开头的 `auth_not_found:`、`auth_unavailable:`。本地错误和正文中间提及相同字样不能证明上游认证池不可用。

排除集合只属于当前请求；后续独立请求正常选路，不改变持久渠道配置。已知候选全部被排除时停止空转，其他兼容入口和普通暂时故障仍保留有界恢复。

已有输出或上游可能接受但结果未知时，继续禁止重放。该补丁防止无效入口跨轮复活，不修复供应商连接、目录或认证池。

## 合成验证

本地数据库和缓存选择器覆盖不同入口接管、已排除入口跨轮不复活、后续独立请求重新选路、暂时故障恢复、精确 503 兼容前缀及输出边界。

真实 Relay 集成验证 `auth_not_found`、`model_cooldown`、`upstream_connection_refused` 可由独立健康入口接手；错误正文仅提及关键词、非匹配状态及本地错误均不触发新增排除。普通测试及目标 race 通过。
