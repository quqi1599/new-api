# CPA 聚合入口重试放大修复

2026-10-17 的本地排查记录关联到：同一客户端请求经 NewAPI 的两个 CPA 协议入口和三个重试轮次，共调用 CPA 六次；CPA 每次最多尝试三个上游，形成最多十八次尝试。聚合入口返回普通 `429 upstream_unavailable` 时，NewAPI 无法知道 CPA 已完成内部尝试；已有永久排除只覆盖部分明确机器码，同协议别名排除也未覆盖这类 429。

## 响应契约

CPA 在完整失败且尚未向下游输出时，发送以下内部响应头，保留原 HTTP 状态、错误码和错误内容：

| 响应头 | 接受值 |
| --- | --- |
| `X-CPA-Retry-Scope` | 单值 `gateway` |
| `X-CPA-Retry-Attempts` | 单值规范十进制整数 `1`–`1048576`，为 CPA 实际上游尝试次数 |

NewAPI 只在原始 HTTP 状态为 429 或 5xx、两个头同时合法、错误有明确上游响应时记录该契约。已收到上述状态和标记后，即使错误响应体截断，也保留已确认的上游拒绝、原状态和尝试次数。缺少头、重复值、越界值、普通请求拒绝和没有该响应契约的本地传输失败均不建立该标记。后续状态映射保留已确认的标记。

## NewAPI 行为

- 当前 CPA 渠道在这一个客户端请求内永久排除，下一轮不能复活；独立渠道仍可接管，独立暂态渠道仍可在预算内下一轮恢复。
- 新契约允许识别同一 CPA 池的 OpenAI/Claude 协议入口：完整基础 URL、凭据摘要、组织、模型映射、请求模型和受支持的头规则必须一致。仅主机相同不足以合并。
- 空覆盖配置及精确 `{"*":true}` 标准透传规则可识别；两种规则分别计算身份。选中请求的有效覆盖必须与渠道配置一致。其他头重写、参数重写和多 Key 入口保持保守，只排除当前已调用渠道，不推断其他渠道属于同池。
- 原有无标记 429/5xx、auth 错误及请求终止错误保留各自策略；不把所有 429 改为请求级终止，也不降低全局重试预算。
- 最终返回标记错误时保留真实、经单行长度校验的 `Retry-After`。不合成新的冷却时间，不修改渠道状态、模型配置或客户限流。

实现位于 [gateway_service_retry.go](../../controller/gateway_service_retry.go)、[error.go](../../service/error.go) 和 [错误类型](../../types/error.go)。

## 本机验证

合成 HTTP 服务经真实 NewAPI `Relay`、数据库与内存选择器，覆盖 Responses/Messages、普通请求与流开始前失败：无标记时同池可调用六次；合法标记时只调用一次；独立备用仍成功。测试还覆盖标准透传配置、动态覆盖负控、非法标记、原错误与 `Retry-After` 保留、状态映射和独立暂态入口下一轮恢复。

跨服务回归 [cpa_nested_retry_integration_test.go](../../controller/cpa_nested_retry_integration_test.go) 使用本机实际 CPA 二进制和合成上游，十二组通过：无头时六次 CPA 请求、十八次上游尝试；有头时一次 CPA 请求、三次上游尝试；独立备用成功。覆盖标准透传配置、Responses/Messages、普通与流开始前失败。其运行需要显式提供测试二进制，不使用生产凭据或客户正文。

本记录描述本地修复与验证；提交、推送、CI 和生产发布按本次实际授权分别执行。

2026-10-21 本地配套修复：CPA 按用户要求遍历全部可用独立 Key，实际次数可能超过8；NewAPI 严格解析新的多位计数，保持单值、规范十进制、实际上游拒绝、429/5xx及非本地错误限制。新增25 Key真实本机CPA二进制联调，防止池已遍历后再次进入同池。此数字上界仅限HTTP元数据解析，不截断CPA候选遍历。
