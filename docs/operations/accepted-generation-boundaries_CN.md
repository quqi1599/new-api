# 解码失败的有界备用补救与 Claude 输出校验边界

## 输出前的文本备用补救

已撤回对 `upstream_response_decode_failed/502` 的全局不可重试标记。解码错误可能发生在上游已经执行、客户尚未收到输出时；本策略明确允许合格文本请求在原有预算内尝试其他合格入口，因此可能增加一次文本生成用量，不代表首次生成没有发生。

补救必须同时满足：实际收到上游错误响应，普通 Chat Completions 或 Responses 文本路径，没有已接收的业务事件或客户输出，没有取消、明确停止约束或预算耗尽，且原请求结构可确认没有不透明状态或由供应商执行的副作用。

原始 502 及被状态映射为其他 5xx 的相同精确机器码使用相同风险门。实际是否重试仍由既有状态策略、指定渠道、亲和停止约束和共享 `RelayRetryState` 决定；映射为 400 不会因此打开重试。原状态、机器码、消息及调用方渠道健康策略保持。

一旦进入补救，本请求所有已失败渠道持续排除，包括随后返回普通错误的备用渠道，不能在下一轮复活；不创建新的 attempt、轮次或 elapsed 预算。不同渠道 ID 只证明选中了其他渠道，不证明其底层供应商或物理上游独立。

## 普通函数工具与完整历史

Chat 的 `type=function` 定义和 Responses 的 function 定义是模型生成的声明，网关不会代客户执行这些函数。完整可见、调用 ID 成对匹配的 function call/result 历史可以参与补救，原 tools 与历史不被删改。

合成 MiMo 形状包含九个普通 function 定义、四组完整 call/result：主入口返回解码 502 后，其他合格入口完成；每次尝试均验证九个工具和四组结果仍存在。与先前全局拒绝相比，该形状现在能够受益。

继续拒绝续接引用（previous_response_id、conversation、item_reference）、加密/不透明状态、未配对的工具历史、供应商托管工具、MCP、computer/shell/code interpreter、媒体创建、异步 background，以及尚未证明语义的 custom 工具、include 或未知结构。含无法审计的参数/运行时头覆盖也不参与本次补救。重复 JSON 对象键会被拒绝，防止风险判定与下游解码器取不同值。

未开放的结构返回原错误，不降级或移除其功能。已有输出、明确 state-owner 错误和传输结果未知等原有屏障保持。

## Claude 输出校验不计渠道惩罚

保留五个生成后输出校验码：`output_invalid_json`、`output_schema_mismatch`、`output_not_json_object`、`output_stream_mismatch`、`output_unknown_tool` 的既有 502 不重试、不惩罚分类。

Claude 流式适配器把流内错误表示为内部 500，因此保留“Claude 错误封装 + 500”的精确分类：原错误不改写，不计自动禁用或熔断惩罚。普通 OpenAI 500 不受影响。不放宽输出校验，不伪造 completed/DONE，不修改 usage 策略。

## 本地验证

- 真实 Relay：Chat/Responses、数据库/缓存、九个 function 和四组结果，主入口解码失败后备用完成；普通文本流式同样完成。
- 对照全局拒绝版本，合格请求原本无法补救；对照只撤销拒绝的旧重试循环，能复现同入口跨轮复活及状态风险请求误重放。
- 全部失败仅遍历合格渠道一次；混合错误、attempt/elapsed 耗尽、取消、指定渠道、亲和停止、已有事件/输出、续接/托管工具均验证边界。
- 502 映射为 500/503 时普通 function 请求仍可恢复，有状态请求仍拒绝；映射为 400 即使配置宽重试范围也停止。
- 实际 Claude 处理器三协议、首事件前后五个校验码回归保留。

全部请求为本地合成测试；本次未提交、推送或部署，原始上游解码故障的处理另行核验。
